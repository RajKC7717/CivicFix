## 1. AI tools used to build this project

**Claude Code (Anthropic) was used extensively** to write this project — backend,
frontend, tests, data generators and documentation. It was used as a pair programmer:
every design decision, every threshold and every metric in this repository was reviewed,
challenged and in several cases measured before being accepted.

Specific decisions that came out of measurement rather than assumption, and which are
documented in the code where they live:

* separating the deduplication match key from the display title (AUC 0.904 → 0.989);
* sorting the match key after discovering word-order sensitivity in the vectoriser
  (identical complaints scored 0.905 instead of 1.000);
* resolving model/lexicon disagreement by the model's *margin* rather than its raw
  confidence (held-out accuracy 97.9% → 100%);
* softening the in-radius distance decay after measuring that the original threshold
  was costing recall for no precision benefit (0.26 → 0.66).

No other AI coding assistant was used. No code was copied from another hackathon
submission or from a tutorial project.

## 2. Third-party data

| Dataset | Source | Licence / terms | How it is used |
|---|---|---|---|
| **311 Service Requests (2010–present)** | NYC Open Data, dataset `erm2-nwe9`, via the Socrata API | NYC Open Data Terms of Use — public data, free to use and redistribute with attribution | 368 **distinct** English complaint-type/descriptor pairs, mapped to our 9 categories, used as supporting vocabulary for the offline classifier and **down-weighted 3:1** against our multilingual corpus. Fetched by `scripts/fetch_nyc311.py`; the app works without it. |
| **OpenStreetMap map tiles** | tile.openstreetmap.org | ODbL 1.0; © OpenStreetMap contributors (attributed on every map) | Base map in the citizen and officer UIs. The app renders correctly without them. |
| **Nominatim geocoding** | nominatim.openstreetmap.org | OSM Foundation usage policy | Forward geocoding of landmark text. Optional — disabled entirely by `GEOCODING_ENABLED=false`. |

### A finding worth recording about NYC 311

NYC 311's `descriptor` field is a **controlled vocabulary, not free text**. The dataset
has millions of rows but only a few hundred distinct complaint phrasings, so paging raw
records returns the same strings thousands of times and teaches a TF-IDF model nothing.
We therefore ask Socrata to `$group` and keep the distinct descriptor set. This is why
the contribution is 368 rows rather than the tens of thousands a naive fetch suggests —
stated here because it changed how the data is used.

## 3. Synthetic data — what is invented, and why

> **All complaint data in this repository is synthetic. No real citizen complaint, no
> real name, and no real phone number appears anywhere in it.**

| Artefact | Status | Detail |
|---|---|---|
| `data/synthetic_complaints.csv` | **Synthetic** | 430 complaints generated by `scripts/generate_synthetic.py` from hand-written templates in English, Hindi (Devanagari), Marathi (Devanagari) and romanised Hinglish. Contains 42 **planted duplicate groups** with ground-truth cluster ids — this is what deduplication is scored against. Deterministic: fixed seed, committed output. |
| `data/wards.geojson` | **Synthetic boundaries, real centroids** | A Voronoi tessellation of twelve *real* Pune locality centroids, clipped to the city bounding box. Verified gap-free and non-overlapping across 3,000 random points. **These are not Pune Municipal Corporation electoral wards.** No PMC ward GeoJSON with an unambiguous licence was available; the file is disclosed as synthetic in the API response, in the map popups, in the citizen footer and here. Drop a licensed real GeoJSON at the same path with `code`/`name`/`zone` properties and it is used unchanged. |
| `data/pois.csv` | **Synthetic** | 61 fictional schools and hospitals placed inside real localities, used for the "within 200 m of a school/hospital" priority bonus. Generic names (`{Locality} Municipal School`); no real institution is named. |
| Phone numbers, e-mails, vehicle numbers in the corpus | **Synthetic** | Injected deliberately (in ~7% of rows) so PII redaction is exercised on realistic input. All use reserved/example ranges. |
| Under-served wards (Kondhwa, Yerawada) | **Synthetic property of the data** | The generator gives two wards a deliberately worse service record so the equity audit has something real to detect. **This is a property of the generated dataset and is not a claim about these real places or about PMC.** |
| Officer names, departments, demo credentials | **Fictional** | `A. Deshpande`, `S. Kulkarni`, `Dr. M. Rane` are invented. Credentials are `officer/officer` etc. and are printed on the login screen on purpose. |

## 5. What is original to this project

Written from scratch for this submission:

* The **multilingual civic lexicon and Devanagari transliterator**
  (`backend/app/pipeline/lexicon.py`) — the term table, the language-identification
  rules, the canonical-English normalisation, and the separation of display title from
  deduplication match key.
* The **deduplication scoring model** — hard gates, the weighted similarity, the
  in-radius distance decay, and the three-band merge/review/new decision.
* The **explainable priority formula** and its YAML policy file.
* The **equity audit** — ward and language parity, flagging rules, and the switchable
  priority adjustment.
* The **eight-stage pipeline** with per-stage logging and per-stage fallbacks.
* The **synthetic data generator**, the ward tessellation, the evaluation harness, the
  95-test suite, both applications, and all documentation.

No pre-existing civic-tech codebase, template or starter kit was used.
